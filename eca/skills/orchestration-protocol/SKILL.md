# ECA 编排协议

主智能体调度 eca 智能体群时的强制护栏。目标：企业级交付质量 + 防遗漏——靠机制门禁，不靠临场记忆。核心信条：提示词不能"确保"任何事，必须完成的动作要挂在机械验证上（跑命令、看输出）。

## 1. 任务分级（过程深度）

| 级别 | 判级标准 | 管道 |
|---|---|---|
| **L0 小改** | 单文件或 ≤3 文件、无接口/契约变更、修复路径清晰 | 直通 code-implementer 或 debugger；硬门禁=机械验证；code-reviewer 快检可选 |
| **L1 中等** | 新功能 / 多文件 / 新接口但限于单模块 | code-architect（精简方案）→ code-implementer → code-reviewer ∥ security-reviewer（并行）→ 修复循环。测试以 implementer 的 TDD 为主；评审发现覆盖不足时追派 test-engineer |
| **L2 大型** | 跨模块 / 重构 / 数据迁移 / API 契约变更 / 安全敏感 | code-architect 完整影响面分析+方案 → **用户确认门** → code-implementer（可分批）→ code-reviewer ∥ security-reviewer ∥ test-engineer → 修复循环 → DoD 终检 |

判级拿不准时取高一级。每个任务的管道必须完整走完对应级别，不得中途降级省环节（这正是防遗漏的关键）。

## 2. 交付验收分级（交付标准，先于判级确认）

| 级别 | 适用 | 验收重点 | 收尾要求 |
|---|---|---|---|
| **系统项目级** | 新系统/大模块从零到可用 | 架构五原则、全局安全（ASVS 按注入级别）、系统级测试、部署复杂度下的交付 | 以安全部署收尾：部署/回滚脚本幂等入库（ops/ 惯例）、凭据由用户亲手配置不经模型、部署后健康检查通过 |
| **功能任务级** | 既有系统上新增功能/较大改动 | 需求理解后**发散→收敛**：枚举功能外延（边界、异常、接口、交互路径、文档），全部收敛交付 | 外延覆盖清单逐项核对后收敛，不做清单外的无限延伸拓展 |
| **fixbug 与体验完善级** | 缺陷修复、小改进、交互打磨 | 根因说明 + 回归测试；体验类改动附前后对比证据；改动最小化 | 全量回归通过；无范围蔓延 |

验收级别与任务分级联动但不等同：验收级别定"交付标准"，任务分级定"过程深度"。级别由用户指令明确（门禁规则 0），以避免无限、无效的延伸拓展。

## 3. 门禁规则（全部强制）

0. **级别确认门**：任务开始前必须确认交付验收级别（2 节三级），未确认不 dispatch；默认逐任务判级后向用户确认，用户可授权会话级默认级别。
1. 评审打回必须修复并复审；修复循环最多 2 轮，超限上报用户裁决。
2. 任何"完成"汇报必须附机械验证命令输出证据（构建/类型/lint/测试，至少其一，按技术栈选全）。
3. L2 方案未经用户确认不进实现。
4. 并行评审 = 单条消息同时 dispatch 多个只读智能体，互不依赖。
5. **验收优先级**：安全缺陷一票否决、直接打回；可维护性问题按类别报告，任一类别低于达标线即打回；性能不设通用硬线，按项目验收清单注入。

## 4. dispatch 模板（领域约束注入，每次派发必填）

```
【任务】<做什么，含交付验收级别>
【领域约束】语言/框架/版本；代码规范；禁区；性能与安全要求(ASVS 级别)；验收清单
【输入】相关文件路径 / 前序阶段产物（方案、改动清单、影响面清单）
【输出协议】该智能体定义中的输出协议
```

智能体本体保持语言/领域通用；具体约束全部在此注入。领域约束缺失时先补齐（依据项目 AGENTS.md/技术栈探测）再派发。

## 5. 类型化 DoD 清单库

- **新功能**：测试（正常+边界+异常）/ 文档同步 / 无游离 TODO / 机械验证通过 / 验收清单逐项核对
- **缺陷修复**：根因说明 / 新增回归测试 / 全量测试通过 / 改动最小化
- **重构**：行为不变（测试为基线）/ 无功能增删 / 影响面清单逐项执行 / 技术债记录
- **API 变更**：向后兼容评估 / 所有消费方更新 / 契约文档同步 / 版本策略说明
- **数据迁移**：迁移脚本 + 回滚脚本 / 测试环境演练 / 数据完整性校验
- **配置变更**：受影响组件枚举 / 默认值与向后兼容 / 敏感项不入库

变更涉及多类时取并集。DoD 由 code-implementer 自查、code-reviewer 核对。

## 6. 降级与边界

- **智能体不可用**（未注册/被禁用/派发失败重试 1 次仍失败）：主会话按该智能体的检查表直接执行并向用户**明示降级**，不得静默假装走了管道。
- **token 控制**：L0 不派评审；并行评审仅 L1/L2。
- **凭据边界**（重申全局规则）：密码/密钥/Token 等凭据内容永不进入任何智能体的上下文；检测只看模式不看值；凭据由用户亲手写入目标机。
- **运维变更**：凡涉及服务器变更，沉淀为可复审的幂等脚本入库（ops/），由本地代码执行。

## 7. 与 superpowers 衔接（场景 → 技能名）

| 场景 | 技能 |
|---|---|
| 实现含测试 | superpowers:test-driven-development |
| 调试排障 | superpowers:systematic-debugging |
| 声明完成前 | superpowers:verification-before-completion |
| 制定/执行计划 | superpowers:writing-plans / executing-plans |

主会话编排时引用；eca 子智能体的提示词已内嵌对应流程要点（子智能体不共享主会话上下文，不能靠引用技能名）。
